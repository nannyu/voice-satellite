# 08. 斐讯 R1 接入服务器 Agent：原厂语音前端桥接方案

版本：0.1（设计基线）
日期：2026-09-20
目标设备：用户的 R1 / 固件 3448
状态：已核对相关仓库代码；`services/stock-gateway/` 已实现 P1 的受限 passthrough/fixed_reply 服务器切片与离线回归，但尚未接入 R1、DNS、真实上游或 Agent，本文接口和验收项均未真机验收。本仓库同时保留 Android 回归客户端、KWS 历史探针和只读取证工具；不修改设备、路由器或任何运行中的服务。

## 1. 决策摘要

主线采用“原厂唤醒、采集、ASR 与播报链路 + 局域网兼容网关 + 现有服务器 Agent”。网关以 `SaifLau/r1-stock-bridge` 的协议处理作为参考及可审计的复用起点，不把其演示服务直接当成完整产品。

停止继续投入 sherpa-onnx。现有 Android 独立采集、Opus/WebSocket 和 echo 测试链路保留为回归与备用，但在原厂模式下不启用独立采集或播放。暂缓原厂 SDK 提取、进程注入、系统签名与 ROM 改造。

本方案替代此前“必须先导出原厂 PCM、后端必须全部自建”的优先级，不覆盖或删除旧取证资料。只有纯代理在打断、会话控制或上游依赖方面触及明确限制时，才进入设备端研究。

所有时间、成功率、数量和资源安排均为拟定设计目标，不是已经测出的产品指标。

## 2. 需求与交付边界

| 用户需求 | 第一阶段交付定义 | 尚须验证的边界 |
|---|---|---|
| 中文唤醒，不绑定个人声纹 | 保留“小讯小讯”，无需逐人注册 | 多位说话人、噪声、播放中成功率；不承诺任意口音均 100% |
| 本地唤醒 | 无外网冷启动后仍能给出本地唤醒反馈 | 原厂初始化是否依赖网络或已有激活状态 |
| 与 Agent 对话 | ASR 文字送入真实 Agent，会话可连续追问 | 原厂每轮可能仍需唤醒词；持续监听不能靠服务器记忆替代 |
| 随时打断 | 等待、播报和音乐中可再次唤醒；旧声音停止，旧轮次不会重新播出 | 无唤醒词直接插话独立验证，不能用唤醒词打断冒充 |
| 工具与家居联动 | 由已有 Agent 决策并执行已授权工具 | 声音不是身份认证，高风险工具保留可信渠道授权 |
| 音乐与有声书 | 媒体链接交给原厂播放器兼容路径，不把媒体变成 TTS | 暂停、恢复、进度、格式支持逐项真机确认 |
| 外部服务可用 | 可接受原厂 ASR 和外部 TTS/模型服务 | 必须识别实际上游和数据流，不能把未知中转当成可信原厂 |

“首版可用”最低门槛是唤醒词打断通过；“免唤醒词自然插话”保持明确的未交付项，不能对外宣称已完成完整自然打断。是否进一步投入无唤醒词插话，依据原厂实测能力和用户对新增改造成本的判断。

## 4. 总体架构

```text
                         R1 / 原厂应用
                本地唤醒、采集、原厂音频处理
                      原厂录音与请求协议
                              │
                     本机/局域网定向路由
                              │
                  Stock Gateway（新增）
                   ┌──────────┴──────────┐
                   │                     │
            原厂协议转发与解析       已验证的 ASR 上游
                   │              原厂或明确允许的服务
                最终识别文字
                   │
          设备映射、会话与轮次管理
                   │
              AgentAdapter
                   │
              已有服务器 Agent
           上下文、工具、家居、媒体搜索
                   │
              文字或媒体动作
                   │
       原厂响应包装、有效轮次检查、返回
                   │
           R1 原厂播报或媒体播放
```

原厂云链路不是通过网关凭空消失：音频或原厂请求仍可能送往外部上游。具体传输内容与目的地址在 P0 记录。保留原厂 TTS 链路也不等于保证 TTS 本身离线。

### 4.1 部署单位

先部署一个 `stock-gateway` 服务，与现有 Agent 分开进程或容器即可。网关内部的协议、会话、适配、诊断是逻辑模块，不拆成多套微服务。初期使用单实例、单会话管理器，按设备串行化状态变化；等待网络时不持有设备锁。

SQLite 可作为拟定的幂等、任务状态和会话元数据存储；不是第一天就引入队列集群的理由。业务会话历史优先由 Agent 维护，网关只保存映射与轮次日志。可先在局域网盒子/现有服务器上运行，不新增设备端推理。

### 4.2 模块职责

| 逻辑模块 | 职责 | 不承担的内容 |
|---|---|---|
| StockProtocolAdapter | 保留必要原厂请求语义、转发 ASR、识别终态、包装响应 | 不直接决定复杂业务、不输出未经验证的原厂状态码 |
| DeviceRegistry | 将可信登记设备与原厂 `ui`、来源网络映射 | 不把 MAC、IP、`ui` 或声音当成强认证 |
| TurnManager | 会话、代次、去重、超时、取消与输出资格 | 不从 HTTP 请求数量推导用户说话次数 |
| AgentAdapter | 对接实际 Agent API，协商取消/任务能力 | 不要求 Agent 假装成某家模型；不重复维护工具规则 |
| SpeechPresenter | 短句、可播报格式、原厂 JSON 输出 | 不默认具备分句推送或播放完成反馈 |
| MediaAdapter | 经允许的媒体结果、播放 URL、暂停恢复策略 | 不把长音频放进对话回答、不默认知道播放位置 |
| Diagnostics | 分阶段耗时、错误、能力与回滚标记 | 默认不保存原始音频、全文或敏感请求头 |

## 5. 正常对话与多轮上下文

### 5.1 单轮流程

1. 用户唤醒 R1，原厂完成采集并发起自身协议请求。
2. 网关转发至已验证的 ASR 上游，并处理识别分片和最终结果。
3. 将确认的最终文本绑定至一个 `turn_id`；分片、轮询和重试不得多次调用 Agent。
4. 严格的设备控制白名单可直接处理暂停、恢复、音量；其余文字送给 Agent。
5. Agent 返回播报文字或允许的媒体动作，网关再次核验轮次有效性。
6. 原厂兼容层输出已通过真机验证的响应；R1 使用原厂路径播报。

取消、失败或超时回复也必须通过同一输出有效性检查，不能只有正常答案做检查。

### 5.2 多轮

网关维护 `device_id → conversation_id`；Agent 维护业务上下文。原厂 `sid` 仅用于对应传输会话，不用作长期聊天 ID。

初始建议同一设备 180 秒无新请求后结束当前短会话；“换个话题/新对话”显式切换。180 秒为可配置体验参数，不是原厂限制。房间共用会话默认不跨天记住个人资料，不自动合并该用户手机、网页上的私有会话。

没有声纹注册只表示无需认人才能唤醒，不代表系统有能力区分谁在说话。多人轮流使用时，不将前一个人的私有数据默认读给后一个人。

服务器保持上下文和音箱保持麦克风监听是两种能力。首版允许每轮先说唤醒词；若原厂支持一段时间内连续追问，再开放该能力，并单独设定空闲结束和隐私指示。

### 5.3 历史与播放状态

区分 `generated`（已生成）、`sent_to_device`（已发送）、`playback_started`、`playback_finished` 和 `interrupted`。纯代理没有可信播放事件时，后两项必须为未知，不能因 HTTP 返回成功就声称用户听完。

旧轮次生成的回答不得无条件追加进当前对话的助手已发言历史；Agent 应支持轮次草稿或提交策略。已经执行的工具效果仍保留真实操作记录，即使回答被打断，不能把操作从历史中抹掉。

## 6. 打断：产品核心与方案门槛

### 6.1 三个互相独立的结果

**本地停声**：用户再次唤醒后，R1 停止当前 TTS 或压低/暂停媒体，开始接收新的声音。

**服务器取消**：网关使旧轮次失效，并向支持取消的 Agent 发出取消请求。Agent 不支持取消时，明确记录无法停止计算，但仍禁止旧输出进入播报。

**旧输出隔离**：新问题开始后，旧 ASR 终态、旧 Agent 结果、旧媒体动作、超时提示及异常回退都不得重新获得输出资格。

三项一起通过，才称为本方案的“唤醒词打断”。只停声不取消，会浪费后台计算；只取消不隔离，会有迟到答案；只丢答案不能停止设备已经缓存的声音。

### 6.2 新轮次判定

可信输入的优先级为：

- 已真机验证、可认证的设备唤醒事件（增强阶段可能取得）。
- 已通过协议取证确认的新录音/新话轮开始标记。
- 只能在最终 ASR 时确认的新轮次。

第三种是延迟观察，不标记成实时唤醒事件。第一版若只有这种信号，必须靠原厂本地停声和丢弃旧响应行为通过竞态测试；否则纯代理不能放行。

不能每收到一个 `/trafficRouter/cs` 请求就加一轮：同一句话可能含多个网络请求。最终 ASR 也可能重传或乱序，不得让迟到的旧识别结果反过来成为最新轮次。[S3][S5]

### 6.3 代次与状态机

每台设备保存 `generation = {gateway_epoch, seq}`。网关每次启动生成不同的 epoch；可信新轮次使 seq 递增。处理中的回调携带创建时的代次，不能自行获取当前代次覆盖旧值。

```text
AWAITING_ASR → AGENT_RUNNING → RESPONSE_READY → SENT_TO_DEVICE
      │              │                │
      └──────────────┴────────────────┴→ SUPERSEDED / EXPIRED / FAILED
```

本地播放状态另存且允许 UNKNOWN，不伪造一个完整设备状态机。

在发送任何会影响 R1 的最终响应之前，核验：设备归属、代次相等、轮次非失效、总截止时间未过、该输出尚未发送。核验和标记提交由同一设备的短临界区完成。实际写网络后无法撤回字节，设备侧已经收到的旧播报仍由原厂中断行为或增强控制层负责。

保留已失效 turn/sid 的 tombstone，防止迟到回调重新打开会话。重启后默认清除未完成输出资格，不自动重放旧播报或未知结果的有副作用任务。

### 6.4 不假设静默响应格式

旧请求不能简单返回空 JSON、HTTP 204 或一段“已取消”文字就当成结束。它们可能触发原厂错误播报、重试或继续占用状态。

P1 必须取得并验证可用的静默结束方式，或者确认原厂会安全放弃旧连接。仅影响传输的必要确认响应与会触发动作的 NLU 终态分开处理。找不到安全终结方式时，列为协议阻塞项，不绕过验收。

### 6.5 何时增加设备端控制层

纯代理仅在以下项失败时增加 `StockControlCompanion`：即时新轮次通知、TTS/媒体停止、旧播放队列清理或可信播放事件。新组件不采集麦克风、不做 KWS、不重新处理音频。

前置条件是查明合法可访问的原厂 IPC/广播/控制接口及其权限。普通 Local Binder 强转并不提供跨进程调用能力。[S11] ADB 日志可以用于实验观测，不能默认成为手机应用可使用的接口或生产必需依赖。

若不存在无需提权的有效控制入口，应形成阻塞报告。Root、注入、原厂签名替换或 ROM 修改需要独立授权，不包含在本方案默认授权中。

## 7. AgentAdapter 接口草案

以下是本项目拟定的内部契约，不是原厂协议，不表示用户当前 Agent 已提供这些 HTTP 路径。实际 Agent 接口未知，先由适配器映射；不要求重写 Agent。

### 7.1 能力协商

启动时记录 Agent 是否支持会话、取消、幂等、独立长任务和结构化工具结果。取消和幂等没有实现，必须明确降级，不把关闭客户端连接当成取消成功。

### 7.2 创建轮次

拟定调用：`POST /voice/v1/turns`。入口鉴权使用服务器间凭据，幂等键为 `request_id`，不是文字哈希。

```json
{
  "schema_version": "0.1",
  "request_id": "req-demo-001",
  "device_id": "r1-living-room",
  "conversation_id": "conv-demo-001",
  "turn_id": "turn-demo-001",
  "generation": {"gateway_epoch": "epoch-demo-001", "seq": 1},
  "input": {
    "type": "text",
    "text": "帮我查一下客厅温度",
    "language": "zh-CN",
    "source": "stock_asr"
  },
  "response_budget_ms": 6000,
  "presentation": {
    "mode": "stock_text_reply",
    "target_sentences": 2,
    "soft_max_chars": 80
  }
}
```

`response_budget_ms` 为适配层收到请求后的剩余处理预算示例，生产中由原厂剩余等待预算和网关总截止时间共同计算。服务端本地使用单调时钟；不要把一台机器的单调时钟时间戳发到另一台后直接比较。

原始用户文本单独传递，不把旧项目的简短回答提示拼进用户指令。播报风格放在 presentation 中，避免覆盖 Agent 的工具、安全或会话逻辑。[S4][S10]

### 7.3 结果、取消和长任务

| 拟定内部接口 | 用途 | 语义 |
|---|---|---|
| POST `/voice/v1/turns` | 创建一次对话处理 | 相同 request_id 与相同内容返回同一任务；同键不同内容报冲突 |
| GET `/voice/v1/turns/{turn_id}` | 查询状态/结果 | 区分 running、completed、cancel_requested、cancelled、failed |
| POST `/voice/v1/turns/{turn_id}/cancel` | 请求取消 | 返回取消请求状态，而不是假定动作已撤销 |

Agent 侧可返回 202 表示已接收；该 202 只存在于网关与 Agent 之间。网关不能未经验证把它直接回给 R1 原厂请求。

```json
{
  "schema_version": "0.1",
  "request_id": "req-demo-001",
  "turn_id": "turn-demo-001",
  "generation": {"gateway_epoch": "epoch-demo-001", "seq": 1},
  "status": "completed",
  "speech": {"text": "客厅现在是二十六度。"},
  "device_actions": [],
  "job_id": null
}
```

工具执行归 Agent；设备媒体动作归网关能力适配层。每项有副作用动作有独立 action_id，不因答案重试再次执行。网关只执行登记且通过验证的动作，不接受任意 shell、任意广播或任意媒体代理目的地址。

### 7.4 长任务语义

第一版不依赖主动播报。长任务只有在 Agent 明确持久接收、返回 job_id 后，才可以向用户反馈“任务已开始，可以稍后查询”。不能把任务未收到、超时或连接关闭描述成已经在处理。

用户本来要求一个持久任务时，新的语音问题默认只打断当前会话输出，不擅自取消该任务；“取消刚才的任务”才取消明确的 job。普通本轮问答任务随轮次失效取消。任务已执行的外部动作不能因取消回答自动撤销。

主动播报、实时进度和长回答分句推送必须在设备播放控制通道通过后开放。

## 8. 时延与播报策略

初版回答建议 1～2 句，以语义压缩而非直接截断数字、否定词或关键条件。当前上游代码会按字符截断，并会聚合 SSE。[S4][S10] 新版本先保留完整短响应，不承诺边生成边播报。

P0/P1 通过固定答案和延迟注入（例如 1、3、5、8 秒）测出原厂有效等待窗口、重试和过期处理。建议首版短问答从用户说完到首声 P95 目标 5 秒；Agent 调用预算从该窗口里扣除已经发生的 ASR、转发、响应包装与播报启动耗时。目标未达到时记录分段耗时，不增加重试掩盖问题。

设置整体请求截止时间，并分别限制连接、读取空闲和执行。Requests 的 timeout 不是整条请求的总耗时上限，持续滴流和重试仍可能拖长时间。[S12] 兼容客户端当前存在多次重试与接口回退，应对有副作用的 Agent 调用关闭盲目重复执行。[S4]

重要控制（停止输出、取消当前轮次）不得排在模型生成队列后面。静态回答测试先测协议和设备启动播报成本，再测 Agent 增量。

## 9. 媒体与连续追问

音乐/有声书作为独立媒体会话保存 track_id、queue_id 和可得的进度。原厂反馈不可得时，progress 必须 unknown，不能根据服务器发送链接时刻推算真实播放位置。

唤醒时，默认先暂停媒体；问答结束后，仅在“此前确实正在播放、未被用户明确停止、媒体会话未变化、播放结束信号可信”同时满足时恢复。没有可信播放结束事件时不靠估算 TTS 时长自动恢复，改成显式“继续播放”。

优先静态可访问音频验证，再加媒体搜索、授权内容和队列。有声书断点续播在可用位置查询/seek 接口确认后交付。媒体文件传输与 ASR/Agent 控制请求使用独立资源预算，避免长音频拖住停止指令。

## 10. 网络部署、安全与故障边界

### 10.1 网络

原项目部署文档提出改写 `aios-home.hivoice.cn`、`asrv3.hivoice.cn`、`log.hivoice.cn`。[S9] 这些是待验证候选，不直接对整个家庭网络全部重写。

设计上让 R1 使用专用 DNS 策略或隔离网段，逐个验证必需域名和路径。网关到上游使用不受 R1 重写影响的解析路径，保持正确 Host 语义，避免请求循环回网关。若实测为 HTTPS/其他协议，先验证兼容性，不通过关闭证书校验宣称支持。

| 入口 | 拟定暴露范围 |
|---|---|
| 原厂兼容 HTTP 入口（按抓取协议，可能为 80） | 仅 R1 所在受控网段/设备 |
| 管理、诊断接口 | 默认 loopback 或独立受控管理网 |
| Agent API | 服务器本机/容器私网；跨机器使用认证与受保护通道 |
| 媒体入口 | 仅音箱访问范围，允许目标和资源类型受限 |

禁止将旧示例中的通用 absolute URL 转发直接暴露为开放代理。禁用未经需要的 cookie 设置和全文调试接口；管理员与设备入口分离。未知上游、样例 IP 和样例 Host 不视为已验证可信配置。[S3][S5]

### 10.2 服务实现

原项目用 `http.server` 接入请求；Python 官方不建议将该模块作为生产服务。[S5][S13] P1 可在隔离局域网使用其行为作协议对照；长期版本需采用合适的服务框架或受控协议入口，并用原厂报文回归验证。单加反向代理不会自动修好会话状态、请求边界和并发问题。

设请求体/响应体大小、读取截止时间、并发和队列上限；规范 Transfer-Encoding、Content-Length、压缩及 hop-by-hop 头处理。保留原厂必要应用层头，不把所有头盲转给 Agent。升级 HTTP 栈不得破坏 Expect:100-continue、分块请求或无 Content-Length 的特殊情况；不明确的格式先抓取再支持。[S5]

### 10.3 隐私与权限

正常日志只保存脱敏设备标识、turn_id、route、耗时和错误码。文本与音频采集只在用户授权的短期诊断模式开启，完成后按指定保留期清理；原厂云自身上传行为需单独观察，不能由网关日志开关推断没有上传。

多人可唤醒不代表多人有权执行所有工具。查询、媒体、有限家居动作和高风险动作分权限配置；门锁、支付、公开发送及权限变更不凭房间里一句声音完成。本文不改变这些动作的用户授权要求。

### 10.4 故障行为

| 故障 | 设计行为 |
|---|---|
| Agent 不可用/超时 | 经验证的短失败响应；本轮失效；不自动补播迟到结果 |
| ASR 上游不可用 | 明确语音交互受限，不声称后端已全离线；不能假定任何语音控制仍有效 |
| 网关不可用/DNS 未回退 | 原厂云不会自动可达；通过明确回滚流程恢复，不承诺自动降级 |
| 原厂仍能本地唤醒但无法对话 | 保留真实诊断状态，区分本地唤醒与远端识别失败 |
| 网关重启 | 更换 epoch，旧输出失效，不重放未知状态工具动作 |
| 网络反复断连 | 有界重连与熔断；取消路径优先；避免无限生成任务 |

## 13. 验收矩阵与测量方式

以下阈值为建议起点。任何硬指标调整需要在报告中记录原因，不能在测试失败后无痕改变标准。

| ID | 场景 | 建议目标 |
|---|---|---|
| A01 | 3～5 人不注册声纹，1/3 米静态唤醒 | 每人分别统计；安静环境各组成功率 ≥95% |
| A02 | 无外网冷启动与原厂唤醒 | 记录是否本地唤醒成功，5 次启动；与对话在线依赖分开 |
| A03 | 固定答案代理闭环 | 连续 20 轮正确，无死锁、卡住和意外旧播报 |
| A04 | 连续语义追问 | 同一会话 10 轮上下文正确；新会话不泄漏旧私密内容 |
| A05 | TTS 播放中再次唤醒 | 至少 30 次；唤醒词说完到旧声停止 P95 ≤500 ms；成功率 ≥95% |
| A06 | 音乐中再次唤醒 | 低/中音量分别至少 30 次；记录停声及新话音完整性 |
| A07 | Agent 延迟时再次唤醒 | 延迟 1/3/5/8 秒组合；新轮生效后旧答不回流 |
| A08 | A 慢、B 快、A 迟到 | 自动化至少 100 组乱序；旧轮有动作的响应输出为 0 |
| A09 | 相同 sid/请求重试/分片重发 | Agent 业务调用和副作用均不重复；用户另说同样一句应算新轮 |
| A10 | 原厂过期与静默终结 | 旧请求结束不触发错误播报、重试风暴或阻塞新轮 |
| A11 | Agent 真取消/不支持取消 | 状态真实；不支持时不得报告已停止后台计算 |
| A12 | 副作用执行后打断 | 不声称撤销；真实效果记录保留；取消响应不重复动作 |
| A13 | 连续人声/电视/音乐负例 | 24 小时受控素材观察误唤醒，初期目标 ≤1 次；注明场景边界 |
| A14 | 重启/断网/上游失败 | 不重放旧答案或未知状态的副作用；能按文档恢复 |
| A15 | 短问答首声 | 用户说完到实际首声 P95 ≤5 秒目标；报告 ASR/Agent/播报分段 |
| A16 | 24 小时常驻 | 无持续内存增长、麦克风冲突、请求积压或服务失联 |
| A17 | 安全与隐私 | 未登记设备/管理入口拒绝；日志无 token、cookie、原始音频 |
| A18 | 回滚演练 | 恢复原厂路由和包状态后原厂闭环可重复；独立链路需互斥切换 |
| A19 | 免唤醒词直接插话 | 独立记录；未通过保持未交付，不用 A05 代替 |
| A20 | 主动播报/自动恢复媒体/断点续播 | 分别有可信控制与反馈才启用；未实现记录 unknown/unsupported |

实际停声与首声使用外部录音、回放波形或同一可信时基的设备事件测量；不能以服务器发送 HTTP 时间代替听到声音的时间。纯代理缺少播放反馈时，在报告中写明测量来自外部，而非运行时已具备该能力。

音量、距离、说话人、网络、模型/Agent 配置和固件状态随报告记录。上述计数用于工程筛查，不代表统计上保证所有人、所有噪声条件的长期性能。

## 14. 回滚与操作授权

P0 前保存包状态、原 DNS/路由规则、代理开关与配置版本。停止现有独立采集/播放后才能恢复原厂语音包；先恢复正常原厂基线，再逐项启用代理。

回滚代理时撤销本方案新增的定向 DNS/路由、清理对应缓存或续租，确认 R1 不再请求旧网关，再停止网关。原厂服务必须保持在已经验证的状态。不要只关闭代理而保留指向它的 DNS。

需要恢复独立 Android 链路时，先关闭该链路，按已有验证方式隐藏冲突原厂包并重启，再启用独立服务；不是每次对话都切包或重启。

实施中的包状态、路由器、权限和对外服务变更逐项获得明确授权。设计资料经用户明确要求提交到仓库；Root、签名替换、固件刷写与不可逆删除不属于本次提交或本文默认动作。

交付：本设计文件、Agent 内部接口样例、验收矩阵 JSON、来源清单、历史实验文档、独立 Android 回归客户端与只读取证工具。验证覆盖文档/JSON 一致性、校验器反例单测、取证工具单测与 Android 本地构建；没有运行新服务、进行新的声学测试或验证原厂 ASR 当前在线状态。
